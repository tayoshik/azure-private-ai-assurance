# Terraform Implementation — Stage 1 (Source Baseline)

**Status:** SOURCE CREATED / OFFLINE TEXT CHECKED; **Terraform CLI `fmt`, `init`, `validate`, `plan`, `apply`: NOT EXECUTED**. Azure live pass **0**, production release **NO-GO**.

This package is the first implementable HCL slice of the existing 55-node Terraform DAG in `tayoshik/azure-private-ai-assurance`. It does **not** contain an operational Azure application, private Application Gateway, OpenAI account, AI Search or Cosmos DB. Those modules will be added only in later slices.

## Contents

- `infra/bootstrap/`: independent resource group, protected StorageV2 account, ARM-managed private Blob container, scoped CI data role, **separate management VNet**, private Blob endpoint and DNS zone/link. Never bootstrap from the remote backend it is creating.
- `infra/modules/foundation/`: workload resource group.
- `infra/modules/network/`: application gateway delegated subnet, App Service outbound delegation, separate web/data PE subnets.
- `infra/modules/private-dns/`: parameterized private DNS zones and workload VNet links.
- `infra/environments/dev/`: composition root with explicit placeholder-only inputs; remote backend requires separate readiness gate.
- `scripts/check_terraform_stage1.py`: offline *textual* fail-closed contract and secret-pattern checks.
- `tests/test_terraform_stage1.py`: 14 Python regression tests, including unsafe-configuration mutations.
- `docs/terraform-stage1-operator.md`: comprehensive command-by-command operator runbook and failure handling.

## Local checks (no credentials)

```bash
python3 scripts/check_terraform_stage1.py
python3 -m unittest discover -s tests -p 'test_terraform_stage1.py' -v
# Only with an approved Terraform CLI:
terraform fmt -check -recursive infra/
```

**Important:** `terraform fmt` is not `terraform validate`. `terraform validate` needs initialized provider plugins in the approved environment. This runtime had no Terraform CLI or provider cache, so neither command was executed here.

All example subscription identifiers are intentionally invalid; real environment data remains in approved protected CI configuration, not in this public GitHub repo.
